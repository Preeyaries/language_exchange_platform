Features

Everything two learners need to find each other and keep talking

A profile built around languages

Registration takes three short steps: account, personal details, then native language, the languages you are learning with a CEFR level for each, interests and a bio.

Partner matching

The Matches screen suggests people who speak a language you are learning and who are learning your native language. You can also search by name or by language.

A feed for practice

Write posts with topics, filter the feed by language, like and comment. English posts can be translated to Thai with one tap.

Follow and message

Follow people you enjoy talking to. Direct messages come with a conversation list and unread counts, and the open chat refreshes every five seconds.

Profiles with a sense of place

Each profile shows language levels as dots, interests, follower counts and a map of the person's city. Email addresses and dates of birth stay private.

Admin panel

Administrators get a separate desktop layout to search and edit users, suspend accounts, promote admins, remove posts and review reports.

The core idea

The matching rule, live

Choose who you are. The list updates with the same rule the API uses: the partner's native language is one you are learning, and the partner is learning your native language.

How it works

From the browser to the database

The React app and the API are served from one address. The browser only ever calls /api, so no server address is stored in the code.

Client

React app

React 18, Vite, React Router, Tailwind CSS, Axios, Leaflet maps

Server

Nginx on EC2

Serves the built frontend and forwards /api to the backend

API

Express, kept alive by PM2

Routes, controllers and middleware for auth, admin checks and validation

Data

MongoDB Atlas

Users, profiles, posts with embedded comments, messages, reports

GitHub Actions Backend tests on a MongoDB containerthen Frontend buildthen, on main only Deploy on the EC2 runner
Security

Private by default

  • Passwords are hashed with bcrypt and never returned by the API
  • Every request re-checks the account, so a suspension applies at once
  • Email and date of birth stay private. Others see a handle and an age range
  • Allowed-field lists stop a client from setting fields like author or likes
  • Ownership checks on posts, comments and messages
  • Rate limiting on login and registration
  • Search text is escaped before it reaches the database
Tests

51 tests on a real database

Jest and Supertest drive the API end to end. The suite uses its own database and refuses to run against one without "test" in its name.

  • Registration, login and current user
  • Posts, likes and comments
  • Profiles, follows and messages
  • Matching and search
  • Private data, protected fields and admin-only routes
  • Suspended accounts and malformed input
Roadmap

Not finished yet

These parts are designed but not complete.

  • Tag management is a screen prototype. Tags are not saved to the database
  • Social sign-in buttons are not connected to a provider
  • Image and voice notes exist in the data model, with no upload feature
  • Translation covers English to Thai only
